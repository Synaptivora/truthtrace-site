产品功能

从采集到结论，全程证据可溯

TruthTrace 的能力围绕一条主线展开：把材料变成证据、把证据变成结构化结论，并让每一句结论都能点回原始出处。

核心流程

四步走完一次核查

1

采集材料

上传聊天记录、截图、PDF 与文件；或选择已连接的钉钉、微信、飞书，按联系人或群名搜索并限定导入范围。每份材料登记为唯一编号的证据。

2

AI 解析与识别

识别人物、还原事件、提取主张与承诺。文本、截图 OCR 与 PDF 解析由解析服务统一处理。

3

独立核查与矛盾标注

逐条主张做证据支持度核查，标出证据之间的差异、时间线冲突与缺口，并给出补证建议。

4

生成可回溯报告

报告优先呈现针对目标的回答、未解决问题与原文依据；技术过程折叠展示，每条引用可点回原文。

三大能力模块

采集 · 推理 · 展示

由 A、B、C 三个模块分工协作，边界清晰、职责明确。

模块 A · 数据接入

多渠道证据采集

独立的证据解析服务，统一响应 POST /parse，把五花八门的材料收敛成结构化的证据。

  • 文本、聊天截图 OCR、PDF 解析
  • 钉钉 / 微信 / 飞书渠道直读与限定导入
  • 空文件、超时、超大输入等边界处理
POST /parse
  → { "evidence": {
        "id": "E1",
        "type": "chat",
        "content": "……"
    } }

每份证据唯一编号，文本引文必须能在 content 中逐字定位。

模块 B · AI 引擎

推理与引用校验

维护 API 与分析校验，确保模型输出「有据可查」。

  • 人物、关系、事件、矛盾、承诺、补证建议的结构化输出
  • 引用不存在的证据或人物 → 服务端拒绝
  • 输入错误返回 400，模型失败返回 502，不回传模型原始错误
AnalysisResult {
  人物  relationships
  事件  timeline
  矛盾  contradictions
  承诺  commitments
  补证  followups
}

交互入口

对话 Agent 与自主调查

「和咪探长聊聊」

右下角对话入口，支持普通聊天、多轮追问、证据关键词检索、分页读取原文与查看已有分析。

  • 18+ 家模型供应商预设，支持自定义接口
  • 兼容 Chat Completions / Messages / Responses 三种协议
  • 引用校验通过后才保存回复

自主调查

输入调查目标，自动安排单点核查、时间线或完整调查，八阶段 Skill 依次执行。

  • 可暂停、继续、取消、纳入新材料修订
  • 人物作为候选，由用户采纳、驳回或修改
  • 本地 SQLite 持久化，支持断点续跑与报告版本
