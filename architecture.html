技术架构

边界清晰的模块化设计

TruthTrace 采用三模块分工架构，以数据契约为唯一接口边界，让三个角色可并行协作、互不越界。

技术栈

现代全栈技术组合

N

Next.js

应用框架，App Router + API 路由，支持静态导出部署。

Ts

TypeScript

全栈强类型，严格类型检查贯穿构建流程。

Z

Zod

数据契约校验，Evidence 与 AnalysisResult 运行时校验。

三模块分工

采集 · 推理 · 展示

接口边界由 src/lib/contracts.ts 的数据契约锁定，任何一方改动契约都必须在 PR 中说明并同步其余两方。

A

数据接入（ingest）

独立解析服务，只实现 POST /parse。负责文本、截图 OCR、PDF、微信/钉钉 MCP 解析。

分支 feat/ingest

B

AI 引擎（brain）

证据模型、矛盾核验、测试集。只改 src/app/api/*、src/lib/ai/*、src/lib/contracts.ts。

分支 feat/brain

C

前端展示（frontend）

工作台、关系图、时间线、交互。只改 src/components/* 与 src/app/globals.css。

分支 feat/frontend

数据契约

结构化结论，一处定义

// Evidence —— 证据
Evidence {
  id, type, content, ...
}

// AnalysisResult —— 结论
AnalysisResult {
  人物   relationships
  事件   timeline
  矛盾   contradictions
  承诺   commitments
  补证   followups
}

前端只消费经过 Zod 校验的结构化结果，不理解 MCP 或模型提示词。这一设计把「模型输出」与「可信结论」之间划出一道硬边界。

引用校验：模型输出会先经过 src/lib/ai/validate.ts 校验，引用不存在的证据或人物会被服务端拒绝，防止凭空编造来源。
错误边界：输入错误返回 400，模型调用或输出失败返回 502；不向浏览器回传模型服务的原始错误。
持久化

本地优先的数据层

当前案件与调查任务支持本地 SQLite 持久化，数据目录默认 .truthtrace/。

路径说明
cases.sqlite案件、不可覆盖的证据版本、任务、事件、报告版本
originals/上传文件的原始字节，以 SHA-256 命名
objects/解析后的材料内容，以哈希命名
connection*.enc本机加密连接（AES-GCM + Windows DPAPI 保护主密钥）
安全设计：密钥不保存于浏览器、报告与任务事件；哈希用于去重与完整性，不代表来源真实性。
